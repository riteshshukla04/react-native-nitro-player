Nitro Player provides first-class Android Auto support with media browsing, playback controls, and connection detection.

## Enable in Configuration

```typescript
import { TrackPlayer } from 'react-native-nitro-player';

await TrackPlayer.configure({
  androidAutoEnabled: true,
});
```

## AndroidManifest Setup

Add the following to your `android/app/src/main/AndroidManifest.xml`. Make sure the root `<manifest>` tag declares the `tools` namespace:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">
```

> The library's own manifest already registers `NitroPlayerPlaybackService` (the Media3 `MediaSessionService` that powers playback and now-playing). For Android Auto **browsing**, you also need to expose the separate `NitroPlayerMediaBrowserService` from your app's manifest — Android Auto only discovers browse trees on services declared in the consuming app.

### Media Browser Service

Inside the `<application>` tag:

```xml
<meta-data
  android:name="com.google.android.gms.car.application"
  android:resource="@xml/automotive_app_desc" />

<service
  android:name="com.margelo.nitro.nitroplayer.media.NitroPlayerMediaBrowserService"
  android:foregroundServiceType="mediaPlayback"
  android:exported="true"
  tools:ignore="ExportedService">
  <intent-filter>
    <action android:name="android.media.browse.MediaBrowserService" />
  </intent-filter>
</service>
```

> ⚠️ **Common pitfall:** declaring the `MediaBrowserService` intent-filter on `NitroPlayerPlaybackService` (or on a non-existent class like `com.margelo.nitro.nitroplayer.service.MediaBrowserService`) will let now-playing work but show an empty browse tree in Android Auto. The class name must be exactly `com.margelo.nitro.nitroplayer.media.NitroPlayerMediaBrowserService`.

### Automotive App Descriptor

Create `android/app/src/main/res/xml/automotive_app_desc.xml`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<automotiveApp>
  <uses name="media" />
</automotiveApp>
```

## Custom Media Library

By default, Android Auto shows all your playlists. You can customize the browsing structure:

```typescript
import {
  AndroidAutoMediaLibraryHelper,
} from 'react-native-nitro-player';
import type { MediaLibrary } from 'react-native-nitro-player';

const library: MediaLibrary = {
  layoutType: 'list',
  rootItems: [
    {
      id: 'favorites',
      title: 'Favorites',
      subtitle: 'Your favorite tracks',
      mediaType: 'folder',
      isPlayable: false,
      layoutType: 'grid',
      children: [
        {
          id: 'top-tracks',
          title: 'Top Tracks',
          mediaType: 'playlist',
          isPlayable: true,
          playlistId: 'playlist-top',
          iconUrl: 'https://example.com/art/top.jpg',
        },
      ],
    },
    {
      id: 'recent',
      title: 'Recently Played',
      mediaType: 'playlist',
      isPlayable: true,
      playlistId: 'playlist-recent',
    },
    {
      id: 'genres',
      title: 'Genres',
      mediaType: 'folder',
      isPlayable: false,
      children: [
        {
          id: 'rock',
          title: 'Rock',
          mediaType: 'playlist',
          isPlayable: true,
          playlistId: 'playlist-rock',
        },
        {
          id: 'electronic',
          title: 'Electronic',
          mediaType: 'playlist',
          isPlayable: true,
          playlistId: 'playlist-electronic',
        },
      ],
    },
  ],
  appName: 'My Music App',
};

if (AndroidAutoMediaLibraryHelper.isAvailable()) {
  AndroidAutoMediaLibraryHelper.set(library);
}
```

### Reset to Defaults

```typescript
AndroidAutoMediaLibraryHelper.clear();
// Falls back to showing all playlists
```

## Starting From the Car

Android Auto can start your app with no UI at all: the process is killed, the driver opens your app on the head unit (or the car resumes music on connect). Nitro Player handles this natively — it creates the player and media session itself and connects the car straight away. Your app's React Native runtime starts in the background (no UI) on the first request that needs it — the driver opens your app, searches, picks a track, the car resumes music, or a track needs its [lazy URL](/docs/api/track-player#lazy-loading) — not merely because the car connected.

For that to work, everything Android Auto needs must be registered at **module scope** (e.g. in `index.js` or a module it imports), not inside a component — components never mount in a headless start:

```typescript
// index.js
import { TrackPlayer } from 'react-native-nitro-player';
import { registerAndroidAuto } from './src/androidAuto';

TrackPlayer.configure({ androidAutoEnabled: true });
TrackPlayer.onTracksNeedUpdate(resolveUrls); // lazy URLs
registerAndroidAuto(); // library, loaders, search, buttons

AppRegistry.registerComponent(appName, () => App);
```

While a track's URL is still being resolved, the player waits for `updateTracks` instead of failing with a "Source error", and URL requests raised before your listener attached are re-sent once it does. Requests that fail because the network is down are re-sent once it is back, and picking the same waiting song again re-sends it.

Some phones (Samsung One UI) stop React Native's JS timers while your app is in the background with the screen on, even while it plays. `fetch` resolves through `setTimeout`, so a `fetch`-based `onTracksNeedUpdate` never finishes there. Resolve URLs with `XMLHttpRequest` (its `onload` needs no timer) or a client built on it such as axios, and avoid `setTimeout` on that path.

When the car sends play on connect ("Start music automatically"), Nitro Player waits up to 10s for your app to restore a queue and resumes it.

## Loading Folders on Demand

Large libraries do not fit in one published tree (Android Auto caps a single result at ~1 MB). Publish a folder with `children: []` and supply its children when the car opens it:

```typescript
AndroidAutoMediaLibraryHelper.set({
  layoutType: 'grid',
  rootItems: [
    { id: 'artists', title: 'Artists', mediaType: 'folder', isPlayable: false, children: [] },
  ],
});

AndroidAutoMediaLibraryHelper.setChildrenLoader(async (parentId) => {
  if (parentId === 'artists') {
    return artists.map((a) => ({
      id: `artist:${a.id}`,
      title: a.name,
      mediaType: 'folder',
      isPlayable: false,
      children: [], // loaded on demand too
      groupTitle: a.name[0], // section header
    }));
  }
  if (parentId.startsWith('artist:')) {
    const playlistId = await materializeArtistPlaylist(parentId.slice(7));
    return (PlayerQueue.getPlaylist(playlistId)?.tracks ?? []).map((t) => ({
      id: `${playlistId}:${t.id}`, // playable items: `${playlistId}:${trackId}`
      title: t.title,
      subtitle: t.artist,
      mediaType: 'audio',
      isPlayable: true,
    }));
  }
  return null;
});
```

Answer within a few seconds; after 10s the folder is shown empty, and a later answer (within a minute) makes the car reload it.

## Search

```typescript
AndroidAutoMediaLibraryHelper.setSearchHandler(async (query) => {
  const playlistId = await materializeSearchResults(query);
  return toPlayableItems(playlistId);
});
```

Registering a handler shows the search button in Android Auto (from the next connection). Voice requests the loaded playlists cannot match are sent to the same handler, and the first playable result is played. Results time out after 7s.

## Session Buttons

Add buttons next to the transport controls in Android Auto and the media notification — for example a favourite heart:

```typescript
let favourite = false;
const showHeart = () =>
  AndroidAutoMediaLibraryHelper.setSessionButtons([
    { action: 'favourite', title: 'Favourite', icon: favourite ? 'heart_filled' : 'heart' },
  ]);

AndroidAutoMediaLibraryHelper.onSessionButtonPress((action) => {
  if (action === 'favourite') {
    favourite = !favourite;
    showHeart();
  }
});
showHeart();
```

Icons: `heart`, `heart_filled`, `star`, `star_filled`, `thumb_up`, `thumb_up_filled`, `plus`, `check`.

## Connection Detection

### Hook

```tsx
import { useAndroidAutoConnection } from 'react-native-nitro-player';

function App() {
  const { isConnected } = useAndroidAutoConnection();

  useEffect(() => {
    if (isConnected) {
      // Load Android Auto media library
      AndroidAutoMediaLibraryHelper.set(library);
    }
  }, [isConnected]);
}
```

### Synchronous Check

```typescript
const connected = TrackPlayer.isAndroidAutoConnected();
```

### Event Callback

```typescript
TrackPlayer.onAndroidAutoConnectionChange((connected) => {
  if (connected) {
    AndroidAutoMediaLibraryHelper.set(library);
  }
});
```

## Voice Search (Google Assistant / Gemini)

Nitro Player supports voice queries like _"Hey Google, play **Daft Punk** on My Music App"_ on Android Auto, the lock screen, and Pixel devices running Gemini. Queries are routed into `MediaSession.Callback.onSetMediaItems` and matched against your loaded playlists — no extra wiring is required on the JS side.

### Manifest

To opt in, declare the legacy `MEDIA_PLAY_FROM_SEARCH` intent on your app's launcher activity. Some Assistant/Gemini surfaces still dispatch through this action, and registering it is what makes Android treat your app as a voice-targetable media app:

```xml
<activity android:name=".MainActivity" ...>
  <intent-filter>
    <action android:name="android.intent.action.MAIN" />
    <category android:name="android.intent.category.LAUNCHER" />
  </intent-filter>

  <intent-filter>
    <action android:name="android.media.action.MEDIA_PLAY_FROM_SEARCH" />
    <category android:name="android.intent.category.DEFAULT" />
  </intent-filter>
</activity>
```

> The library's own `NitroPlayerPlaybackService` already declares the same intent-filter, so the modern `MediaSession` path works out of the box. Adding it to your launcher activity is what lets Assistant pick your app by name (_"…on My Music App"_).

### How matching works

When the user issues a voice command, Assistant/Gemini sends a `MediaItem` whose `requestMetadata.searchQuery` carries the spoken query, plus a `MediaStore.EXTRA_MEDIA_FOCUS` bundle indicating whether they asked for an artist, album, genre, playlist, or title. Nitro Player resolves it like this:

| Spoken phrase | Match strategy |
|---|---|
| _"Play **Discovery**"_ (album focus) | Playlist whose title contains the album, or tracks whose `album` field matches |
| _"Play **Daft Punk**"_ (artist focus) | Tracks whose `artist` matches; falls back to playlist title |
| _"Play the **Workout** playlist"_ | Playlist whose title matches |
| _"Play **One More Time**"_ (title focus) | Track whose `title` matches |
| _"Play music"_ (empty query) | Resumes the current playlist, else the first non-empty one |

If nothing matches, the query goes to your [search handler](#search) when one is registered; otherwise the controller surfaces a spoken error rather than silently failing.

### Tips for better recognition

- Make sure your `TrackItem` metadata (`title`, `artist`, `album`) is populated — voice matching is text-based and only works as well as your tags.
- Load playlists into `PlaylistManager` before the user speaks; voice search only sees what's loaded.
- Test by long-pressing the home button on Android Auto's head unit, or saying _"Hey Google, play X on \<your app name\>"_ on a phone with the app installed.

## Testing with Desktop Head Unit (DHU)

1. Install the [Android Auto Desktop Head Unit](https://developer.android.com/training/cars/testing/dhu)
2. Connect your device via USB
3. Run: `./desktop-head-unit`
4. Your app's media library should appear in the media tab

## MediaItem Types

| `mediaType` | Behavior |
|---|---|
| `'folder'` | Browsable container — `children`, or `children: []` to [load on demand](#loading-folders-on-demand) |
| `'playlist'` | Playable — links to a `PlayerQueue` playlist via `playlistId` |
| `'audio'` | Single playable audio item — `id` must be `${playlistId}:${trackId}`, or `${playlistId}:${trackId}#${index}` for a song that appears more than once in the playlist |

Any item can set `groupTitle`; consecutive items sharing one are listed under that header.

## Layout Options

| `layoutType` | Display |
|---|---|
| `'list'` | Vertical list with text and icons |
| `'grid'` | Grid of artwork tiles |

Each folder can override the parent's layout type with its own `layoutType`.
